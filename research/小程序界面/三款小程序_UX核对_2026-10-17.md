## 充值流程：可参考，但首版应简化

腾讯云《自动充值》文档更新于 2026-09-07。它记录的小程序路径为：

首页 → 快速充值 → 线上充值/填写金额 → 支付并设置自动充值 → 选择规则与金额 → 微信签约与支付 → 开通结果 → 查看已设置规则。

“我的 → 余额”还能查看、调整或取消自动充值；“首页 → 收支明细”查看充值记录。以上是文档记录，未执行交易。

借鉴点是明确的金额确认、结果反馈、规则管理和记录入口。沐仞首版建议先做好单次购买；自动充值若后续提供，应单独展示触发条件、扣款金额及取消入口，不与一次性购买混淆。

来源：[腾讯云费用中心：自动充值](https://cloud.tencent.com/document/product/555/123893)。充值增加账户余额；服务购买或续费另有业务含义，不能把充值成功直接当作服务已经可用。

## 对我们小程序的建议流程

以下是基于既有范围草案提出的设计建议，不是上述三款产品的观察结果，也不表示已经实现。

**个人使用：** 选服务 → 查看用途、计费规则和权益 → 登录 → 确认购买 → 支付结果/到账状态 → 立即使用 → 查看结果及本次消耗 → 历史记录。

重点处理两条回路：

- 从任务中遇到额度不足：保留输入 → 购买 → 回到原任务，由用户确认继续执行。
- 支付后关闭小程序：重新进入后可查订单及到账状态；到账后直接进入工作台。

**企业使用：** 选择企业空间 → 核对角色和当前余额 → 管理员购买 → 到账 → 分配成员额度 → 成员使用 → 查看团队消耗与账单。

成员无购买权限时提供“联系管理员”路径；个人余额和企业余额分别显示，不自动互相扣费。

建议延续草案中的“发现 / 工作台 / 订单 / 我的”四个入口。订单页分开显示购买订单与消费明细；消息先作为页面入口，不必为了模仿腾讯云新增独立底栏。首版仍围绕 AI 额度购买与实际使用，GPU 租赁未确认为本次范围。

现行方案以小程序预览的 [README](../../03_官网与产品/官网源码/mini-preview/README.md) 为准（2026-10-18 起；原 MINIPROGRAM_PLAN.md 等旧方案已删除）。本文上面的"四个入口"建议早于现行方案，现行底栏为模型市场 / API 接入 / 体验 / 我的。
